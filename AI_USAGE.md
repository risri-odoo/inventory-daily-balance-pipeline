## Problems found and fixed during the build (facts from the build)

- **Incremental rebuild barely faster than a full rebuild** (1.1×). Found by the first 100k benchmark: both
  read the whole ledger. Fixed by a filterable `NOT EXISTS` view, two indexes, and reading only the affected
  pairs (3.2×, load 48 s → 22 s). Commits `14f3e36` (baseline) and `87d9b1a` (fix).
- **Intermittently failing test / random run order.** Runs were ordered by a 1-second timestamp plus a
  random run_id suffix. Now ordered by insertion order. Commit `02b0b05`.
- **Process mistake:** commits `87d9b1a` and `27b469d` were pushed while that intermittent test was
  failing. The assistant's shell command checked the exit status of `tail` instead of `pytest`. The fix
  followed within minutes, and later pushes were gated on pytest's own exit code.
- **Mutation checks:** in Phase 3, two key lines were deliberately broken in a scratch copy, to confirm the
  tests catch them (they did).
- **Dashboard escaping test gap (Phase 8):** a mutation check showed that removing `html.escape` from the
  dashboard did not fail any test, because the hostile test data only reached the embedded JSON. A test that
  puts a hostile value into a server-rendered section (the run log's `error_message`) was added. Both escaping
  mutations (HTML and JSON) now fail the intended tests. The template filling was also changed to a single
  pass, so data containing a placeholder name like `__DATA__` cannot be replaced.

- Writing first drafts of all documentation, the data dictionary and the verification map.
